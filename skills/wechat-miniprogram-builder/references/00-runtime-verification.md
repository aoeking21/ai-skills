# 运行时核验协议

## 目的

微信平台规则变化频繁。任何涉及数字、资格、类目、接口或审核尺度的结论，都必须在执行时核验，不能沿用历史教程。

## 必须核验的动态事实

- 注册数量、认证费用、备案材料与处理周期。
- 主体类型与可用能力。
- 服务类目、前置审批和行业资质。
- 微信支付、虚拟支付、订阅或其他付费能力。
- 流量主开通条件、广告样式、分成、结算与频控规则。
- 云开发资源、套餐、接口、模型与 AI 能力资格。
- 隐私保护指引、用户信息授权和权限调用要求。
- 上传、审核、加急、灰度、发布与搜索收录规则。
- 分享、推广、诱导行为、外链和内容治理规则。

## 权威顺序

1. 用户当前可见的微信公众平台后台和开发者工具提示。
2. 微信官方开发文档、官方公告和官方运营规范。
3. 对应监管部门的正式公开文件。
4. 其他资料只能提供线索，不可单独支持关键结论。

## 核验输出格式

```text
核验日期：YYYY-MM-DD
结论：
适用主体或类目：
官方依据：
仍不确定的部分：
对当前方案的影响：
```

## 冲突处理

- 后台提示与旧文档冲突时，以当前后台可执行状态和最新官方说明为准。
- 多份官方材料冲突时，优先发布日期更晚且适用范围更具体的材料。
- 无法核实时，明确写“待后台确认”，并提供不依赖该事实的保守方案。
- 不把“通常”“有人通过”“教程说可以”写成平台规则。

## 时间锚点

回答动态规则时必须写绝对日期。历史数字可用于说明变化趋势，但必须标为历史值，并禁止据此做当前预算或上线承诺。
