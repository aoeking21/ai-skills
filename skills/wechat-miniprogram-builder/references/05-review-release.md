# 审核、发布与驳回修复

## 提审前

- 核心流程能在真机完成。
- 每个按钮、链接和权限都有实际用途。
- 页面无测试文案、占位数据、死链和空白页。
- 名称、简介、截图、类目和实际功能一致。
- 隐私声明与代码调用一致。
- 测试账号、体验路径和特殊操作说明完整。
- 广告、支付、分享和用户内容符合当前规则。
- 服务端正式环境、域名、证书、限流和监控已配置。

详细项目见 `assets/release-checklist.md`。

## 版本说明

版本说明写事实，不写宣传口号：

```text
本版本提供：
1. [核心功能]
2. [用户操作路径]
3. [本次修复或新增]
4. [涉及权限及用途]
5. [审核测试说明]
```

## 驳回修复顺序

1. 原样保存驳回意见、截图和时间。
2. 找到审核员实际触发的页面与操作。
3. 区分规则问题、实现问题、说明问题和资质问题。
4. 查当前官方依据。
5. 选择最小合规修改。
6. 更新代码、后台声明、截图和版本说明。
7. 完成针对性回归测试。
8. 重新提交并保留证据。

不要依赖“换审核员可能通过”。

## 发布策略

发布前准备：

- 回滚版本。
- 服务监控和错误日志。
- 用户反馈入口。
- 数据指标定义。
- 灰度或小范围验证方案，若平台当前支持。

上线后先验证错误率、核心完成率和用户反馈，再扩大推广。
