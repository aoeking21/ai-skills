# Global Priority Contract V1.0

本合同统一真人写真任务中的用户指令、身份真值、连续项目规则、摄影物理和审美模块优先级。

## 1. 先判定任务模式

进入任何 Route、Preset、Beauty、Lighting 或 Composition 模块前，先判定：

- `identity_preserving_edit`：目标仍是参考图中的同一位授权成年人。
- `series_continuity`：同一人物的长期连续项目。
- `new_portrait_generation`：没有具体真人身份锁定要求。
- `reconstruction`：允许明显改变场景、机位、姿态或成像机制。
- `restoration`：以原片内容保真和修复为主。

任务模式决定哪些属性属于不变量，不能用一个全局优先级机械覆盖所有场景。

## 2. 统一优先级

### P0 安全、成年与授权边界

任何模块不得覆盖。

### P1 用户本轮明确任务与显式修改项

包括任务类型、人物数量、输出数量、画幅、明确要求保留或改变的项目、目标模型和输出方式。

用户明确允许改变发型、服装、背景、年龄表现、姿态或构图时，这些字段成为显式 override。

### P2 当前任务要求保留的人物身份不变量

在 `identity_preserving_edit` 与 `series_continuity` 中至少包括：

- 可识别脸型与五官比例
- 关键骨相与自然不对称
- 参考图可见且未被用户要求改变的独特特征
- 人物之间的独立身份映射

风格、妆容、美颜、灯光、服装、Route 和 Overlay 不能静默覆盖这些不变量。

### P3 已确认的连续项目 Profile

包括用户明确确认的体态、眼镜、发型、纹身、长期系列固定项等。若与 P1 冲突，以本轮显式指令为准，并记录为本轮 override，不能偷偷修改永久 Profile。

### P4 解剖、重力、衣料、风、水和环境物理

审美要求需要通过物理可实现的方式表达。出现冲突时优先修复因果关系。

### P5 摄影事件与空间关系

每张图建立主事件、人物位置、前景/背景关系、动作阶段、视线目标和现场因果。

### P6 构图、光影、美颜、镜头与风格

这些属于优化层。优化必须服从 P0 到 P5，不允许为了“更漂亮”破坏身份、任务数量、原片保真或物理逻辑。

### P7 默认值、Route 默认、Overlay 与装饰词

仅在上层没有明确约束时补全。

## 3. 冲突处理算法

1. 标记冲突字段。
2. 找到冲突双方的优先级与任务模式。
3. 保留高优先级字段。
4. 将低优先级目标改写成可兼容的摄影结果。
5. 无法兼容时删除低优先级默认值，不删除用户明确要求。
6. 生成前做一次 parameter propagation audit。

## 4. 真人身份与审美冲突

当任务明确要求“仍是同一个人”时：

`identity similarity > anatomy continuity > event validity > composition/light > beauty/style`

如果用户明确要求改变某个身份相关属性，例如年龄表现、发型或特定可见特征，只改变被点名字段，其余身份不变量继续锁定。

## 5. 多人物规则

多人任务必须建立 `reference_image -> subject_id -> screen_position` 映射。禁止串脸、复制脸、把一个人的发型或独特特征迁移给另一人。

## 6. 禁止隐式永久写回

某次任务里的服装、体型修辞、场景、姿态、妆容和特殊效果都属于 task instance。除非用户明确升级为长期 Profile，否则不能写回人物真值层。
